参考修改器与起源心金不是同一套存档格式，因此这里只比较功能模块和实现思路，不直接复用其偏移、字段或编号。

## 二、参考修改器的功能模块与实现方式

### 1. 存档载入、解析、校验和导出

参考修改器先把存档拆成固定区块，建立区块映射，读取安全密钥和区块校验值；宝可梦记录还有独立的数据校验。修改后重新计算区块校验、宝可梦校验，并镜像到另一份存档副本后下载。

当前项目已经有 512 KiB 双副本、队伍记录解密/加密、General/Storage CRC-16 校验和导出，但没有参考修改器那种按区块读写的通用层。当前实现的可见风险是：修改队伍宝可梦的 136 字节主体后，没有同步写回队伍记录后面的缓存能力值/当前 HP 等字段；参考修改器有 `partyStatsWrite` 专门处理这一层。

### 2. 训练家信息和资源

参考修改器可读取和修改：训练家姓名、性别、训练家 ID、游戏时间、金钱、游戏币，并提供金钱、游戏币和奖励类快捷操作。

当前项目没有训练家信息页，也没有金钱、游戏币、奖励或快捷资源操作。

### 3. 队伍和 PC 盒子

参考修改器支持：

- 队伍和 18 个 PC 盒子展示；
- 队伍内交换位置；
- 队伍与盒子之间转移；
- 盒子内交换/移动；
- 拖动和移动模式；
- 删除单只宝可梦；
- 清空当前盒子；
- 新增宝可梦，并在必要时修复队伍记录。

当前项目已经支持队伍/盒子查看、新增、编辑、删除和导出，但缺少移动模式、拖动交换、队伍与盒子转移、盒子清空等操作。当前“新增到队伍”依赖现有队伍第一只宝可梦作为模板，也没有完整重建队伍缓存。

### 4. 宝可梦基础信息和显示状态

参考修改器的编辑器包含：种族、昵称、闪光、性别、等级、经验、性格、特性、携带道具、精灵球，以及来源、相遇等级、地点、原训练家 ID、亲密度等字段。性别、闪光和能力值由 PID、物种数据、性格、IV/EV 等共同计算或重建。

当前项目只支持种族 ID、等级/经验、性格、特性槽、携带道具、四个技能、EV、IV。缺少昵称、闪光、性别、精灵球、亲密度、来源、相遇等级、地点、原训练家 ID 等字段。当前经验换算采用 `等级³` 近似，没有按物种成长率计算；修改性格通过寻找相同奇偶 PID，可能改变闪光和性别判定。

### 5. 能力值、种族值和编辑后预览

参考修改器读取种族基础能力值，并根据等级、性格、IV、EV 计算六项能力值；同时显示当前能力值和种族值，支持突破 EV 上限和招式学习限制的开关。

当前项目没有种族值/能力值预览，也没有物种成长率、性别比例、蛋组等静态数据驱动的编辑校验。

### 6. 技能和来源信息

参考修改器提供四个技能槽、技能名称目录、学习限制控制，以及精灵来源/遇见信息。

当前项目支持四个技能槽和技能 ID 选择，但名称依赖临时目录/远程资源，未内置完整起源心金技能表，也没有学习限制和来源字段。当前数据包已经加入 921 个技能名称及参数，后续可直接接入。

### 7. 背包管理

参考修改器按存档格式读取各个道具口袋，可以添加、删除、改数量，并按口袋分类显示。

当前项目也有八个口袋的增删改，但原来的偏移和容量是标准 HGSS 假设，不适用于起源心金 4.03，导致口袋内容错位。已用用户提供的 4.03 存档验证出正确布局：

| 口袋 | 起始偏移 | 格数 |
|---|---:|---:|
| 普通道具 | `0x630` | 165 |
| 重要道具 | `0x8C4` | 50 |
| 招式机器 / 秘传机 | `0x98C` | 168 |
| 回复药品 | `0xC2C` | 40 |
| 树果 | `0xCCC` | 64 |
| 精灵球 | `0xDCC` | 24 |
| 战斗道具 | `0xE2C` | 13 |
| 邮件 | `0xE60` | 12 |

因此，用户反馈的“精灵球里出现树果、分类错位”等问题的直接原因是口袋区间从 `0xB4C` 开始被按旧布局解释，而不是名称表本身的问题。

### 8. 图鉴、特殊道具和快捷奖励

参考修改器有图鉴全开/清空、特殊道具和奖励快捷操作。

当前项目没有图鉴编辑，没有训练家资源/奖励模块，也没有特殊道具批量操作模块。

## 三、当前项目已经有的功能

- 双副本存档读取和导出；
- 队伍 6 格、PC 18 盒 × 30 格展示；
- 宝可梦记录解密、校验、基础编辑；
- 新增、删除、编辑队伍和盒子宝可梦；
- 背包八个口袋的添加、叠加、删除、清空；
- 存档 General/Storage CRC 校验；
- 技能、物品、宝可梦选择器的基础框架；
- 本地 ROM 道具解码试验代码。

## 四、建议新增/修正模块

### P0：必须先完成的 4.03 基础层

1. **内置静态数据层**：不再要求用户导入 ROM；内置道具名称、描述、参数、图标、技能、宝可梦/形态、特性和种族数据。
2. **正确的背包布局层**：使用上表的 4.03 偏移和容量，所有双副本读写、添加、删除、清空都走同一套布局定义。
3. **道具名称和图标**：道具列表显示名称、描述、ID 和本地 PNG 图标；不使用远程图片。
4. **特性真实名称显示**：根据物种特性表、存档特性槽、PID 奇偶和隐藏特性标志显示实际名称；写入仍只写可验证的存档字段，不把名称伪装成可写编号。
5. **队伍缓存同步**：编辑队伍宝可梦后同步计算和写回队伍缓存能力值、当前 HP、等级等字段。
6. **经验和能力值计算**：按物种成长率计算等级/经验，加入基础能力值、IV、EV、性格和等级的能力值预览。

### P1：参考修改器的核心操作补齐

1. 队伍/盒子交换、移动、转移和盒子清空；
2. 训练家姓名、性别、ID、游戏时间、金钱和游戏币；
3. 宝可梦昵称、闪光、性别、精灵球、亲密度、来源、相遇等级、地点、原训练家 ID；
4. 技能名称、参数和学习限制；
5. 图鉴全开、清空和逐项编辑；
6. 特殊道具、奖励和快捷资源操作。

### P2：增强功能

1. 物种/形态的完整选择与形态数据；
2. 宝可梦合法性检查和写入前风险提示；
3. 存档区块级诊断和修改前后差异报告；
4. 常用批量操作，例如批量添加、批量清空、批量修复队伍缓存。

## 五、已经生成的数据资源

`originhgss-4.03-data.js` 是可由 HTML 直接加载的静态资源，不读取 ROM。当前包含：

- 791 条道具名称和描述；
- 791 条道具原始参数；
- 791 个 32×32 本地图标 Data URI；
- 921 条技能名称及参数；
- 327 条特性名称；
- 1441 条宝可梦/形态种族数据；
- 4.03 背包偏移和格数定义。

特性显示的原则是“由物种数据和存档字段推导”，不是把任意名称写成特性编号。道具分类的原则是“以存档口袋布局为准”，不是根据跨版本通用 ID 范围猜测。
